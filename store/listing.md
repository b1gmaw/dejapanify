## Summary / short description

**English** (Edge allows 132 characters, AMO 250):

```
Fixes the half-width/full-width (半角・全角) guessing game on Japanese web forms. Converts your text to whatever each field actually wants.
```

```
日本語のフォームでよくある「半角・全角」の入力ミスを自動で修正します。フィールドごとに必要な文字幅へ自動変換。
```

## Full description

**English:**

```
Japanese web forms enforce a character-width convention that has no equivalent
in other languages. The same character exists in two Unicode forms — half-width
(半角) "1500001" and full-width (全角) "１５００００１" — and a given field
usually accepts exactly one of them.

Which one is rarely marked on the input itself. It's printed in Japanese beside
the field (「半角数字で入力してください」) or hidden in a pattern attribute.
Meanwhile your IME produces whichever form its current mode happens to emit. So
you type a phone number that looks correct, submit, and get a validation error
you cannot visually distinguish from what you typed. Then you retype it by hand.

dejapanify reads what each field actually asks for and converts your text to
match.

  フリガナ    やまだ たろう      →  ヤマダ　タロウ
  郵便番号    １５０－０００１   →  1500001
  メール      ｅｘａｍｐｌｅ＠…  →  example@…

HOW IT DECIDES

It does not guess. It collects signals and converts only when they are
conclusive:

  • pattern attributes      — what the site actually enforces
  • the printed instruction — 「半角数字で入力してください」
  • autocomplete            — postal-code, tel, email
  • type and inputmode
  • field names and labels  — name_kana, 「フリガナ」

A field labelled 「フリガナ」 converts on its own, because that is unambiguous.
A field labelled only 「住所」 is left alone, because rewriting an address on a
hunch is worse than doing nothing.

WHAT IT WILL NEVER DO

  • Touch password, hidden, file, date or checkbox inputs
  • Convert a field it could not identify
  • Convert meaning — 山田 never becomes ヤマダ, only width changes
  • Act while your IME is mid-composition
  • Send anything anywhere

HOW IT WORKS

Conversion runs when you leave a field, and again as a sweep when you submit,
which catches autofilled values you never focused. After each conversion a small
notice shows what changed, with a one-click undo. Ctrl+Z also works.

Everything is configurable: turn off individual conversion types, adjust how
confident it must be before acting, or disable it per site.

PRIVACY

No data collection. No network requests. No account. The extension contains no
fetch, no XHR and no remote scripts — every conversion happens locally in your
browser. Open source (MIT): https://github.com/b1gmaw/dejapanify
```

**日本語:**

```
日本語のウェブフォームには「半角・全角」という、他の言語にはない文字幅の
区別があります。同じ文字に半角「1500001」と全角「１５００００１」の2つの
形があり、入力欄はたいてい片方しか受け付けません。

しかしどちらが必要かは、入力欄そのものにはほとんど書かれていません。欄の
横に「半角数字で入力してください」と書かれているか、pattern属性に隠れて
います。一方でIMEは、そのときのモードに応じた文字を出力します。その結果、
正しく見える入力をしたのにエラーになり、見た目では違いが分からないまま、
手で入力し直すことになります。

dejapanify は、各入力欄が実際に求めている形式を読み取り、自動で変換します。

  フリガナ    やまだ たろう      →  ヤマダ　タロウ
  郵便番号    １５０－０００１   →  1500001
  メール      ｅｘａｍｐｌｅ＠…  →  example@…

判定のしくみ

推測はしません。次のような手がかりを集め、確実な場合にだけ変換します。

  • pattern属性          — サイトが実際に検証しているルール
  • 画面の注意書き        — 「半角数字で入力してください」
  • autocomplete属性      — postal-code、tel、email など
  • type / inputmode 属性
  • 項目名やラベル        — name_kana、「フリガナ」など

「フリガナ」というラベルだけで変換します（意味が明確なため）。一方
「住所」だけの欄は変換しません（確証なく書き換えるほうが有害なため）。

しないこと

  • パスワード・非表示・ファイル・日付・チェックボックス欄の変更
  • 判別できなかった欄の変換
  • 意味の変換（山田がヤマダになることはありません。幅のみ変換）
  • IMEでの入力中の動作
  • 外部へのデータ送信

使い方

入力欄からフォーカスが外れたときに変換し、送信時にもう一度フォーム全体を
確認します（自動入力された値もここで拾えます）。変換後は小さな通知が表示
され、ワンクリックで元に戻せます。Ctrl+Z でも取り消せます。

変換の種類ごとのオン/オフ、判定の厳しさ、サイトごとの無効化が可能です。

プライバシー

データ収集なし。通信なし。アカウント不要。fetch も XHR も外部スクリプトも
含まれておらず、すべてブラウザ内で完結します。
オープンソース（MIT）: https://github.com/b1gmaw/dejapanify
```

## Permission justification

Stores ask why each permission is needed. Answers:

**`storage`**

> Stores the user's own preferences: which conversion types are enabled, the
> confidence threshold, and per-site enable/disable lists. No personal data and
> nothing derived from page content is stored.

**Content script on `<all_urls>`**

> Japanese websites are not confined to a single domain or TLD, so the
> extension cannot know in advance which pages contain Japanese forms. The
> content script takes no action unless the page looks Japanese and a field's
> own attributes or printed instructions identify the character width it
> requires. It reads and rewrites only form field values, makes no network
> requests, and transmits nothing.

**Data collection**

> None. Declared in the Firefox manifest as
> `data_collection_permissions: { required: ["none"] }`.

### If asked to justify it

> The extension has no network code of any kind: no `fetch`, no
> `XMLHttpRequest`, no `WebSocket`, no `sendBeacon`, and no remote scripts. It
> requests one permission, `storage`, which holds only the user's own settings
> (which conversions are enabled, a confidence threshold, and per-site
> enable/disable lists). It declares no host permissions and has no background
> script. Form values are read and rewritten in page memory at the moment the
> user leaves a field, and are never stored or transmitted. The package contains
> no third-party code: `package.json` declares no runtime dependencies, and
> everything in the build output comes from the project's own source.
